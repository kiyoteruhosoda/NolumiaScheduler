# ADR-0003: Outlook の JSON は手元に取り込まず、そのままサーバーへ送る

- 状態: 承認
- 日付: 2026-10-19
- 関連: task #537、サーバーの ADR-0054 決定 6、ADR-0002

## 背景

2026-10-07 に足した Outlook の取り込みは、Power Automate が OneDrive に書く JSON を 15 分ごと（とファイルの変更から 5 秒後）に読み、
手元の予定（読み取り専用）として持っていた。サーバーの ADR-0054 決定 6 で、JSON を読むのはサーバーになった。

## 決定

- `ExternalCalendarSyncHost`（殻。周回の時計とファイルの見張りだけ）は、手元へ取り込む代わりに `OutlookFeedSender`（Infrastructure）を呼ぶ。
- `OutlookFeedSender` はファイルの中身を**読み替えずに** `PUT /api/calendars/{id}/outlook-feed` で送る。送る前に JSON として最後まで読めるかだけ確かめる
  （OneDrive が書き換えている途中のものを送らない。0.5 秒・1 秒あけて 3 回まで読み直す）。中身の解釈はサーバーの仕事。
- 送る先のカレンダーは、最初に送るときに `POST /api/calendars/imported`（名前「Outlook」・仕事・`source.type = OUTLOOK_PUSH`）で作り、
  その id を `external-calendar.json` の `serverCalendarId` に覚える（ほかの設定はそのまま残す）。
- 覚えた id が 404（サーバーで消された）か 409（「PC から送る」のカレンダーでない）なら、作り直して 1 回だけ送り直す。
- 送れなかったら（ログインしていない・つながらない・断られた）ログに残して次の周回で送り直す。中身は丸ごとなので溜めない。
- 送った回はサーバーの「取り込んだ回」として写しに戻ってくる（ADR-0002 の 7）。鳴らすのも、その回のリマインダー。
- 手元へ取り込む仕組み（`ExternalCalendarSyncService`・`PowerAutomateJsonCalendarSource`・`IExternalCalendarSource`）は消した。
  読み替えの規則（リマインダーの 15/5/1 分・非公開・終日・長さ 0 は 1 分）はサーバーへ移った（#535）。

## 理由

- 読み替えを 1 か所（試験の回るサーバー）に置くため（サーバーの ADR-0054 決定 6 の理由）。アプリでは「置いた JSON がそのまま届く」ことだけを試験で守る。
- 送る前に JSON として読めるか確かめるのは、書きかけのファイルをサーバーへ送って 422 で断られる回を減らすため（断られても次の周回で直るが、ログが汚れる）。

## 影響

- サーバーへ移す前（手元の保存のまま）の間は、手元に前に取り込んだ Outlook の予定が古いまま残る。移す道具は Outlook の予定を移さず
  （ADR-0054 決定 8）、移した後はサーバーの取り込んだ回を出すので、古いものは見えなくなる。
