# ADR-0008: 「連携の状況」ウィンドウで Outlook とサーバーのやり取りを見せる

- 状態: 承認
- 日付: 2026-10-21
- 関連: ADR-0003（Outlook の JSON をそのまま送る）、ADR-0005（Alarm Debug を外した）、サーバーの ADR-0054 の決定 6・7

## 文脈

ADR-0005 で Alarm Debug を外した後、「Outlook の予定が出ない」ときに何が起きているかを画面から見る手段が無くなった。
Outlook の予定は 4 段を通る: Power Automate がファイルを書く → アプリがサーバーへ送る → サーバーが取り込む →
アプリが写しを読む。どこで止まっているかはログを開かないとわからず、設定画面の「移した日時」もどの時間帯か書いていなかった。

## 決定

1. 左の欄の下に「連携の状況」を置き、別ウィンドウで開く（選んでも表示中のカレンダーはそのまま）。
   見せるもの: 気になる点／サーバー（ログイン・移した日時・写しを読んだ時刻と最後の結果・写しの件数・読めずに飛ばした項目）／
   Outlook（送る設定・ファイルの場所と更新時刻と大きさ・サーバーのカレンダー・最後に送ろうとした回と最後に送れた回）／
   アプリにある今日の Outlook の予定／最近のログ（ExternalCalendar と警告以上）。ボタンは「今すぐ送る」「今すぐ読む」「コピー」「ログのフォルダ」。
2. **時刻はすべて PC の時刻に時差を書き添える**（`2026/10/20 11:14:20 (UTC+09:00)`。`DiagnosticTime`）。設定画面の「移した日時」も同じ書き方にする。
3. 判断（「気になる点」）は Core の `SyncStatus.Diagnose` に置き、CoreTests で守る（ADR-0001）。ウィンドウは書き出すだけ。
   本文の項目名は Alarm Debug と同じく英語の固定（ログと並べて読むため）、見出し・ボタン・「気になる点」は英日の両方。
4. 送りと読みの結果は `SyncActivity` に覚える（メモリだけ。ログを読み直さない）。`ServerCalendarStore` は読めずに飛ばした項目を `Skipped` に残す（これまでは黙って捨てていた）。
5. Outlook を送れたら、その場で写しを読み直す（これまでは次の 5 分ごとの読みまで画面に出なかった）。

## 理由

- 4 段のどこで止まったかが 1 画面で切り分けられ、コピーしてそのまま渡せる。
- 「どこ時間か」を読む人に推測させない。サーバーは UTC、ログは時差付きなので、PC の時刻に時差を添えれば突き合わせられる。
