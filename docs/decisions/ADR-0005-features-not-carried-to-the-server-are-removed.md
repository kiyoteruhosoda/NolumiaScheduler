# ADR-0005: サーバーへ持っていかない機能をアプリから外す

- 状態: 承認
- 日付: 2026-10-19
- 関連: task #537、サーバーの ADR-0054（背景の「持っていかない」と決定 7）、ADR-0004

## 決定

| 機能 | どうしたか |
|---|---|
| 終わった予定の自動削除 | ADR-0004 で外した（サーバーへ切り替えた後に動くとサーバーの予定を消すため、切り替えと同じ PR） |
| Alarm Debug | 画面（`AlarmDebugWindow`）と左の欄の項目、`IAlarmService` の調べるための口（予定のアラームの一覧・鳴った印・説明の行・試しに鳴らす）を外した。Core の `AlarmApplicationService` の同じ名前の口は試験が使っているので残す |
| 営業日カレンダーの画面 | 一覧と編集の画面・その ViewModel・左の欄の項目・その画面の Playwright の試験を外した。営業日はサーバーの休みの層から作る（ADR-0002 の 6）。休みの日はサーバーの設定画面で直す |
| 公開範囲・予定の種類 | 編集画面にはもう出ていなかった（作るときも直すときも「公開」・種類なしで保存していた）ので、画面の変更は無い。**集約の項目（`Visibility`・`EventType`）は残す**: 移す道具（ADR-0004）が手元の予定の公開範囲を読んでプライベートのカレンダーへ振り分けるため。サーバーから読んだ予定は常に「公開」・種類なし |
| 上の画面だけが使っていた文言 | 英語・日本語の両方から 30 件を外した |

- 手元の保存の形（JSON の `business-calendars\` と SQLite の `business_calendars`）は変えない。サーバーへ移す前の版の控えとして残る。
- 営業日シフトの編集画面の「どのカレンダーで数えるか」の選択は残す。サーバーへ切り替えた後は、サーバーの休みの層 1 つだけが選べる。

## 理由

- 画面の殻は CI でビルドされない（ADR-0001）。消す範囲は「消した画面と、それにしか使われていないもの」に絞り、残る画面のコードには手を入れない。
