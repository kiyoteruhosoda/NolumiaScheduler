# ADR-0004: PC の予定は「サーバーへ移す」で 1 回だけ移し、移した印でサーバーの読み書きへ切り替える

- 状態: 承認
- 日付: 2026-10-19
- 関連: task #537（AC2）、サーバーの ADR-0054 決定 7・8、ADR-0002、ADR-0003

## 決定

### 移す道具（`ServerEventMigrator`、Infrastructure）

- 読む元は今の手元の保存（`storage.json` が選ぶ JSON か SQLite。`ICalendarEventRepository` 越し）。
- 送り先は `POST /api/calendar/events/import`（1 回 50 件。サーバーの上限は 100 件）。各予定に `client_ref` = 手元の `EventId`（GUID）。
  サーバーは同じ `client_ref` を二度は作らないので、途中で落ちてもやり直せば続きから入る。
- 写し方（サーバーの ADR-0054 決定 8 の表）:

  | Windows | サーバー |
  |---|---|
  | 単発・繰り返し（規則・飛ばした回・動かした回）・題名・場所・説明・タイムゾーン・色・通知 | 同じ。Windows のタイムゾーン名（`Tokyo Standard Time` など）は IANA 名にする。開始は分の単位に切る |
  | 公開範囲が `Private`・`Confidential` | プライベートのカレンダーへ（サーバーにプライベートの予定のカレンダーが無ければ「プライベート（PC から）」を作る） |
  | それ以外 | 既定のカレンダー（仕事） |
  | 規則の営業日シフト（営業日カレンダーの名指し） | 名指しを外し、シフトだけ残す |
  | Outlook から取り込んだ予定（`ExternalOrigin` あり） | 移さない（ADR-0003 の送り口で入り直す） |
  | 予定の種類・公開範囲そのもの・版・作った日時・上書き（`OVERRIDE`）の例外 | 持っていかない |

- 全部入ったら `migrated-to-server.json`（送った数・新しく作った数・もうあった数・プライベートへ送った数・飛ばした数・日時・サーバー）を置く。
  途中で失敗したら置かない。**手元の予定のファイルは消さない**（控え。消すのは持ち主）。

### 切り替え

- 殻の組み立て（`App.xaml.cs`）は、起動時に `migrated-to-server.json` があればサーバーのリポジトリ（ADR-0002）を使い、
  無ければ今の手元の保存を使う。切り替えは再起動で行う（動いている間に保存先を差し替えない）。
- サーバーを使うときは、起動時と 5 分ごとに写しを読み直す（`ServerRefreshHost`）。最初の見本の予定（`DefaultEventSeeder`）は入れない。
- 設定の画面に「Scheduler のサーバー」の欄を足した: 今どちらで読み書きしているか、ログイン／ログアウト、
  「この PC の予定をサーバーへ移す」（ログインしていて、まだ移していないときだけ出る）。判断は Infrastructure にあり、画面は呼んで結果を出すだけ。

### 終わった予定の自動削除を外す

サーバーの ADR-0054 で持っていかない機能。サーバーの読み書きに切り替えた後に動くと、サーバーの予定を消してしまうので、
切り替えと同じ PR で外した（`PurgeExpiredEventsService`・`EventExpirationService` とその試験、`AlarmService` の呼び出し）。

## 理由

- 移し終えた印で切り替えるのは、「移す前にサーバーを向く」（空のサーバーを見る）と「移した後も手元を向く」（二重に書く）のどちらも起きないようにするため。
- `client_ref` で突き合わせるのは、送った直後に落ちたときも二重にしないため（サーバーの ADR-0054 決定 8 の理由）。
