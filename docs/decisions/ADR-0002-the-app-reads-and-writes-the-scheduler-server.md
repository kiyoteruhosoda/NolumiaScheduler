# ADR-0002: 予定はサーバーで読み書きし、手元には写しを持つ（ログインと HTTP のリポジトリ）

- 状態: 承認
- 日付: 2026-10-19
- 関連: task #537、サーバーの ADR-0054 決定 7（Windows アプリの役割）・決定 6（取り込んだ回のリマインダー）、ADR-0001

## 背景

サーバーの ADR-0054 決定 7 で、予定の正本は Scheduler のサーバー（scheduler.nolumia.com）になり、このアプリはその端末になった。
決まっていること: assay の public client でログイン（PKCE・ループバックの戻り先・トークンは DPAPI）、今のリポジトリの口
（`ICalendarEventRepository` など。同期の呼び出し）の裏を HTTP に替える、手元の写し（メモリと `server-cache.json`）、
書き込みはつながっているときだけ、409 で取り直す、アプリの知らない項目を送り返す、識別子はサーバーの整数を文字列に、
営業日シフトの休みの日はサーバーの休みの層から、取り込んだ回も読んで出し Outlook の回は回のリマインダーで鳴らす。

この ADR は、それをどう組んだかと、ADR-0054 に書いていない細部の判断を残す。

## 決定

### 1. 置き場

すべて `NolumiaScheduler.Infrastructure` に置き、CoreTests で試験する（ADR-0001: 判断は殻に書かない）。

| 置き場 | 中身 |
|---|---|
| `Auth/` | WinTrack（forge `kyon/wintrack` の `src/WinTrack.Core/Auth`）を写した PKCE・ループバックの受け口・OIDC・`SignInSession`。暗号化は `ISecretProtector` の向こう（DPAPI の実装は殻） |
| `Server/ServerSettings` | 向き先と client。既定は本番（`https://scheduler.nolumia.com`、client `nolumiascheduler-win` = `f0c601eaa4ea98d17f8ebdc73eb70761`、戻り先 `http://127.0.0.1:48663/callback`）。データのフォルダの `server.json` で差し替えられる（stg を向けるときなど） |
| `Server/SchedulerApiClient` | サーバーの口。すべて Bearer。401 は 1 回だけトークンを取り直す |
| `Server/ServerContracts` | 口の形（サーバーの `calendar_schemas.py`・`calendar_set_schemas.py`。#535 で足す口は #535 と合わせた形） |
| `Server/ServerEventMapper` | サーバーの予定 ⇔ アプリの `CalendarEvent` |
| `Server/ServerEventWritePlanner` | 「アプリが保存した予定」→「サーバーのどの操作か」 |
| `Server/ServerCalendarStore` | 手元の写し（メモリと `server-cache.json`）・読み直し・書き込み |
| `Server/ServerCalendarEventRepository`・`ServerBusinessCalendarRepository` | 今のリポジトリの口を写しで満たす |
| `Server/ServerDaysOffCalendar` | サーバーの休みの層 → アプリの営業日カレンダー 1 つ |

### 2. 保存（`Save`）をサーバーの操作に読み替える

サーバーの口は操作ごと（作る・単発を直す・系列を直す・回を飛ばす／戻す／動かす／動かしたのを戻す・消す）だが、
アプリのリポジトリの口は「予定を丸ごと保存」。ADR-0054 は口の形を保つと決めたので、**保存のたびにサーバーの写しと比べ、
次の 1 手だけを決める**（`ServerEventWritePlanner.NextStep`）。その手を送り、サーバーの答えを新しい写しにして、また次の 1 手を聞く。
手が無くなったら終わり。

- 比べるのは「サーバーへ送る形（JSON）」どうし。違えば「サーバーが持つものが変わる」ということ。
- 系列の変更（題名・時刻・規則・終了日・色・通知）を先に送り、回の操作（飛ばす・戻す・動かす・戻す）はそのあと。
  開始時刻を変えると、サーバーは飛ばした回などの鍵を付け直す。毎回サーバーの答えから次を決めるので、付け直した鍵も版も推測しない。
- 同じ手が 2 回続いたら止める（サーバーが思わぬ形に整えたとき、送り続けないため）。
- 「この回だけ」はアプリでは「系列のその回を飛ばす」＋「単発を作る」の 2 回の保存なので、サーバーでもその 2 つになる。
  サーバーの「この回だけ」の口（系列のタスクを引き継ぐ）は使わない。**定常業務（分類がタスク）の回を Windows で「この回だけ」直すと、
  新しい単発はタスクを結ばない予定になる**。直したいときは Web の画面で。（口の形を保つ決定 7 を優先した。要るなら後で、
  アプリの「この回だけ」をサーバーの口へ直接つなぐ）
- 上書き（`OVERRIDE`）の例外はサーバーの口に作る手段が無い（サーバーは回を別の予定に分ける）。読んだものはそのまま持ち、送らない。

### 3. アプリの知らない項目を送り返す

予定を直す・系列を直すときは、カレンダー・分類（`event_type`）・結んだタスク（`task_id`）を**写しにあるサーバーの値のまま**送る。
アプリの集約（`CalendarEvent`）には足さない（ドメインを変えずに済み、JSON・SQLite の保存とも食い違わない）。
新しい予定はサーバーの既定のカレンダーに入る。**編集画面のカレンダーの選択（ADR-0054 決定 7 の最後）はこの PR では入れていない**
（写しに `NewEventCalendarId` の口だけある。殻の変更なので後の PR で）。

### 4. 識別子

サーバーの整数の id を文字列にして `EventId` にする。アプリが作った新しい予定の GUID は、作った後はサーバーの id に置き換わる
（写しの中に「GUID → サーバーの id」の対応を残すので、同じ GUID で引いても見つかる）。

### 5. 手元の写しと書き込み

- 写しは起動時に `server-cache.json` から読み、つながれば読み直す。読み直しで何も変わらなければ変更を知らせない
  （知らせるとアラームの「鳴った」印が消え、鳴ったばかりのものがまた鳴りうる）。
- `FindById` は毎回写しから新しく作った集約を返す。アプリのサービスは読んだ集約を直してから保存するので、保存に失敗しても写しは汚れない
  （画面は変更の知らせで描き直され、元に戻る）。
- 書き込みはつながっているときだけ。失敗は `ServerException`（つながらない・断られた）で、手元には溜めない。
- 409 は写しを読み直してから知らせる（次の操作はサーバーの今の版から始まる）。
- 書き込みはリポジトリの口が同期なので、送る間は呼んだ側（画面）が待つ。送る処理は別のスレッドで走らせ、写しの更新と変更の知らせは
  呼んだスレッドで行う（画面のスレッド以外から画面を触らない）。
- 予定は全期間を読む。休みの日は今日の前後 365 日、取り込んだ回は 60 日前から 400 日先まで（サーバーは 1 回 800 日まで）。

### 6. 休みの日

サーバーの規則をそのまま写す（サーバーの `DayOffLayers`・`BusinessDayShiftService`）: 稼働する曜日は営業日の層の曜日（無ければ月〜金）、
休日は「休みとして数える」層の日だけ（曜日の休みは休日ではない）、営業日は稼働する曜日のうち休日でない日。
これを 1 つの `BusinessCalendar`（id `server-days-off`）にし、サーバーから読んだ予定の営業日シフトはこれを指す。
アプリの今の展開・アラーム・画面のコードは変えずに、サーバーと同じ回になる。休みの日はサーバーの設定画面で直す（アプリからは直せない）。

### 7. 取り込んだ回

`GET /api/calendars/imported-occurrences` の回を、読み取り専用の単発の予定（`ExternalOrigin` 付き）として一覧に混ぜる。
今までの Outlook の取り込みと同じ見え方・同じ鳴らし方（回の `reminder` を通知にする。無ければ鳴らさない）。
サーバーの回の id は応答の中でだけ一意なので、id はカレンダー・開始・題名から作る（読み直しても同じ回は同じ id）。
アラームの切り替えは手元だけ（次の読み直しまで）で、サーバーへは送らない。

## 理由

- 1 手ずつ決める形にしたのは、まとめて計画すると、系列の変更で鍵が付け直された後の回の操作を推測で組むことになるため。
  サーバーの答えを毎回正にすれば、推測が要らない。
- 送り返す項目を集約に足さなかったのは、移す道具（ADR-0054 決定 8）が読む手元の保存（JSON・SQLite）の形を変えたくないため。

## 影響

- 殻（`App.xaml.cs`）をこのリポジトリに切り替える配線・ログインの画面・定期の読み直しは、後の PR（移す道具と一緒に）。
- サーバーの口の形が #535 で変わったら `ServerContracts` を直す。
